# 全国水果产区数据系统补充 — 设计文档

**日期**: 2026-07-18
**状态**: 已批准
**范围**: 全国 34 个省/自治区/直辖市

---

## 1. 背景与目标

`fruit_data.xlsx` 当前有 178 条水果记录、238 条产区记录，覆盖 26 个省级行政区。通过对现有数据的分析发现：

- **省份覆盖不均**：四川 22 条 vs 天津 1 条，8 个省份完全缺失（内蒙古、吉林、黑龙江、青海、西藏、台湾、香港、澳门）
- **品种覆盖不全**：桃、李、杏、枣、柿、枇杷、杨梅、百香果、火龙果等 25+ 种常见水果品种在数据中缺乏或极少条目
- **部分产区信息不完整**：44 条记录缺少乡镇级别产地信息
- **存在重复数据**：6 组（同品种+同省份+同城市重复）
- **某些省份代表性不足**：如湖北省仅 3 条记录，作为水果大省远不能反映实际情况

**目标**：以可验证的权威数据源为依据，系统性地核验和补充全国水果产区数据，确保每条记录可追溯、可验证。

---

## 2. 核心原则

### 2.1 数据真实性

| 原则 | 说明 |
|------|------|
| 零虚构 | 不推测、不编造产地、品种、季节信息 |
| 可追溯 | 每条新增/修改记录标注数据来源 URL |
| 宁缺毋滥 | 查不到权威来源的字段宁可留空并标注"待核实" |

### 2.2 验证标准

| 字段 | 验证要求 |
|------|---------|
| 品种名 + 产地（省/市/县/乡） | **必须** ≥2 个独立来源，或以 GI 认证/名特优新名录为唯一权威源 |
| 上市季节 | **必须** 有农业技术资料或政府公示数据支撑 |
| 乡镇信息 | **优先** 从 GI 认证/名特优新名录中提取，无来源则留空并标注 |
| 坐标 | 通过高德 API 根据省/市/县/乡自动查询，不手动填写 |
| 描述文本 | **必须** 来自权威来源原文摘录，标注来源 |

## 3. 权威数据源

| 优先级 | 数据源 | 覆盖内容 |
|--------|--------|---------|
| P0 | 国家地理标志产品（GI）名录 — 农业农村部 | 品种名、产地精确到乡镇、品质特征 |
| P0 | 全国名特优新农产品名录 — 农业农村部 | 品种名、产地、特征描述 |
| P1 | 中国特色农产品优势区名单 — 农业农村部 | 品种+产区（省/市/县级） |
| P1 | 各省农业农村厅公布的特色农产品名录 | 省级精确数据 |
| P2 | 中国绿色食品发展中心认证数据 | 品种+产地交叉验证 |
| P2 | 国家农产品质量安全追溯平台 | 产地坐标、上市时间 |

## 4. 实施架构

### 4.1 阶段划分

```
阶段1: 研究采集        →  阶段2: 清洗验证        →  阶段3: 写入补坐标       →  阶段4: 校验报告
(WebSearch+WebFetch)     (Python 脚本)             (Python+高德API)          (Python 脚本)
```

### 4.2 阶段 1 — 深度研究采集

**方式**：使用 WebSearch + WebFetch 工具，按省份×品类逐批搜索权威数据源，人工审核确认后结构化存入 `_collected_data.json`。

**搜索策略**：
- 第一轮：逐省份搜索"XX省 地理标志产品 水果" / "XX省 名特优新农产品 水果"
- 第二轮：针对缺失品种（桃、李、枣、枇杷、百香果等）全国搜索
- 第三轮：交叉验证——对每条候选数据用第二个来源确认

**输出**：`_collected_data.json`，每条记录带 `sources[]` 字段。

### 4.3 阶段 2 — 清洗与交叉验证

**脚本**：`phase2_validate.py`

```python
# 核心逻辑
1. 读取 _collected_data.json
2. 与现有 Excel 数据逐条比对：
   - 品种+省+市+区县 完全匹配 → 跳过（已存在）
   - 品种+省+市匹配，区县不同 → 标记为补充信息
   - 品种名在现有数据中存在，省份不同 → 新增产区
   - 品种名完全不存在 → 新增品种+产区
3. 交叉验证：
   - sources >= 2 → verified: true
   - sources == 1 → verified: false, confidence: low, 写入但标注
   - 上市季节无来源 → 根据品种通用周期推断，标注 season_source: "inferred"
4. 去重检查：
   - 与现有数据去重
   - 新增数据内部去重
5. 输出：
   - _verified_new.json (验证通过，待写入)
   - _unverified.json (来源不足，待人工确认)
   - _merge_conflicts.json (与现有数据冲突，待处理)
```

### 4.4 阶段 3 — 写入 Excel + 坐标补全

**脚本**：`phase3_write.py`

```python
# 核心逻辑
1. 备份原文件 → fruit_data_backup_20260718.xlsx
2. 逐条写入：
   a. Sheet1「水果产品库」新行：
      - ID 自动递增（F182+）
      - 17 列按 server.py schema 填入
      - 农历月份从公历月份自动计算（参考 server.py _auto_fill_lunar）
   b. Sheet2「产区映射表」新行：
      - 调用高德 API geocode(province, city, district, town) 获取坐标
      - 坐标查询失败 → 重试 3 次 → 仍失败设 (0,0)，标记待处理
      - 若乡镇为空，坐标降级到区县级查询
      - fruitIds 关联到对应水果 ID
   c. Sheet3「成熟度曲线」：如新增品种需要新曲线类型，评估后添加
3. 保存 Excel
4. 调用 server.py regenerate_html() 重新生成前端嵌入式 JSON
5. 输出写入报告
```

### 4.5 阶段 4 — 一致性校验与报告

**脚本**：`phase4_verify.py`

```python
# 校验项
1. 生命周期一致性：用 server.py validate_season_consistency() 逐条验证
2. 坐标范围检查：lng 在 73-135，lat 在 18-54
3. 重复检查：品种+省+市+区县 四元组唯一
4. 关联完整性：每个水果 ID 在 Sheet2 有对应产区行
5. 现有 6 组重复处理：
   - 平和大溪琯溪蜜柚 (F010/F108) → 合并
   - 梅州金柚 (F013/F109) → 合并
   - 苍溪红心猕猴桃 (F046/F107) → 合并
   - 烟台大樱桃 (F070/F093) → 合并
   - 彭阳红梅杏 (F075/F086) → 合并
   - 蒲江猕猴桃 (F117/F159) → 合并
6. 输出报告：变更摘要、新增/修改/去重记录数、未处理项清单
```

## 5. 容错与边界情况

| 场景 | 处理方式 |
|------|---------|
| 来源仅 1 个 | 写入但标记 `verified: false`, `confidence: low` |
| 乡镇查不到 | 乡镇留空，坐标降级到区县级 |
| 季节月份不确定 | 根据品种通用生长周期推断，标注 `season_source: "inferred"` |
| 高德坐标查询失败 | 重试 3 次，仍失败设 (0,0)，标记待人工处理 |
| 写入冲突/异常 | 写入前备份，异常回滚 |
| 农历计算异常 | 捕获异常，设值为 0 |
